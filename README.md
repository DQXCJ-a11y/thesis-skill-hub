# 🎓 thesis-skill-hub

**面向中文理工科硕士论文的开源 AI 审查与写作辅助工作流**

本项目不是论文生成器，也不是单纯的 prompt 收集仓库。  
它更像一套可以直接复用的论文辅助工作流：帮你把论文审查、结构检查、章节修改、表达优化这些高频任务，整理成可直接投喂给 Claude / ChatGPT / Gemini 的 `SKILL.md`。

适用平台：Claude / ChatGPT / Gemini 网页版（无需 CLI、无需编程）

---

## 这是什么？

很多人在写硕士论文时都会遇到同样的问题：

- 不知道论文结构有没有问题
- 不知道每一章到底该怎么写
- 不知道 AI 生成内容哪里“像 AI”
- 不知道把论文丢给大模型后，怎样才能让它真正按论文标准审查，而不是只给一些空泛建议

GitHub 上虽然已经有一些优秀的论文写作相关 skill、prompt 和规则文件，但它们通常分散在不同仓库里，风格不一致，能力边界不清晰，普通用户很难直接拿来稳定使用。

**thesis-skill-hub 想解决的，不是“有没有 prompt”，而是“如何把论文辅助这件事变成一套普通学生也能稳定复用的工作流”。**

本项目当前核心内容是：

- 收敛并整理论文场景下真正有用的审查规则
- 将分散的 skill 合并为一份可直接使用的 `SKILL.md`
- 让用户无需编程，也能把论文 PDF 交给大模型做相对规范的辅助分析
- 持续迭代适合中文理工科硕士论文的审查与修改流程

---

## 这个项目适合谁？

本项目主要面向以下用户：

- 正在写中文硕士毕业论文的学生
- 尤其是理工科、工科方向的论文写作者
- 想借助 Claude / ChatGPT / Gemini 做论文辅助检查的人
- 不想折腾复杂工具链，只想“复制 → 上传 → 开始分析”的普通用户

如果你最需要的是：

- 论文整体结构检查
- 各章节内容是否跑偏
- 逻辑链条是否顺
- 语言表达是否空泛
- AI 痕迹是否明显
- 修改意见是否更具体可执行

那这个项目会比较适合你。

---

## 这个项目不是什么？

为了避免误解，这里把边界说清楚：

**本项目不是：**

- 不是自动代写论文工具
- 不是正式查重系统
- 不是学术不端规避工具
- 不是导师意见替代品
- 不是保证“论文一定过”的神器
- 不是保证研究创新性判断准确的系统

**本项目能做的是论文辅助，不是学术责任替代。**  
它更适合作为你写作和修改过程中的一个“辅助检查器”和“对话式工作流”。

---

## 它和直接问大模型有什么区别？

直接把论文发给大模型当然也能得到回答，但问题通常是：

- 回答不稳定
- 审查标准不统一
- 经常只给空泛建议
- 不会按论文章节去看问题
- 很难重复复用
- 不同平台、不同会话下表现波动很大

本项目的价值不在于“发明了一个更聪明的 AI”，而在于：

**把论文辅助这件事，整理成一套更稳定、更可复用、更适合普通用户的输入方式。**

也就是说，这里的重点不是“模型变强了”，而是“工作流变清楚了”。

## 30 秒上手

1. 打开 [`SKILL.md`](./SKILL.md)，全选复制
2. 打开 [claude.ai](https://claude.ai)、[chatgpt.com](https://chatgpt.com) 或 Gemini，新建对话
3. 先发送下面这段话：

```text
请你完整阅读以下工作指令，阅读完毕后只需回复「已就绪，请提供论文内容」：

【粘贴 SKILL.md 全文】
推荐使用方式

为了让效果更稳定，建议按下面方式使用：

方式一：整篇审查

适合想先看整体问题的人。

示例指令：

请按照 SKILL 中的标准，对这篇论文进行完整审查，并按“整体问题 + 分章节问题 + 优先修改建议”的结构输出。
方式二：单章精修

适合你已经知道某一章问题比较大，想集中修改。

示例指令：

请重点审查第3章，只指出逻辑、结构、表达和方法描述上的问题，并给出可直接修改的建议。
方式三：答辩前总检查

适合论文基本成型后，做最后一轮问题筛查。

示例指令：

请从论文结构完整性、章节衔接、表达规范性、AI痕迹风险、摘要与结论一致性几个方面做一次总检查。

当前核心思路

项目当前的重点不是做“大而全”的论文平台，而是先把一个开源、小而准、可直接用的论文辅助能力做扎实。

当前优先方向包括：

让 SKILL.md 在论文审查场景下更稳定

让输出结果更贴近真实修改需求

降低普通用户的使用门槛

明确适用边界，减少过度承诺

逐步沉淀更清晰的论文辅助工作流

适用范围

当前更适合以下场景：

中文理工科硕士学位论文

常见的 5 章 / 6 章 / 7 章结构论文

需要结构审查、表达优化、章节检查的论文修改阶段

使用 Claude / ChatGPT / Gemini 网页版进行对话式辅助

当前不保证完全适用于：

文科、社科类论文

博士论文

高度依赖学科专门术语规范的论文

需要严格格式校验的最终送审版文档

需要正式查重、正式盲审标准的场景

已收录与参考来源

本项目会参考 GitHub 上已有的优质论文 skill / prompt / 写作辅助仓库，并在此基础上做筛选、去重、合并和适配。

当前参考方向包括但不限于：

论文大纲审核

章节仿写与表达优化

中文论文审查规则

AI 痕迹识别与弱化

文献辅助阅读与整理

后续如果仓库结构完善，会将详细来源单独整理到 docs/SKILL_SOURCES.md 中。

开源原则

这个项目希望保持下面几个原则：

实用优先：先解决真实写论文时最常见的问题

边界清晰：不夸大 AI 能力，不制造“万能感”

普通人可用：尽量不依赖编程和复杂环境

持续迭代：根据实际使用反馈不断调整

开放协作：欢迎提交问题、经验和改进建议

欢迎贡献什么？

如果你愿意参与，比较欢迎这几类贡献：

提交更稳定的论文审查规则

提交不同学科下的适配建议

提交真实使用反馈

提交输入输出示例

提交 README、文档、说明书优化建议

提交更适合普通用户的使用流程设计

如果后续补齐 CONTRIBUTING.md 和 Issue 模板，会进一步规范协作方式。

后续计划

项目后续更值得做的，不是无节制堆功能，而是沿着这几个方向持续优化：

优化 SKILL.md 的结构和可维护性

从“单一大文件”逐步走向“按场景拆分的模块化能力”

增加真实输入输出示例

增加更明确的使用说明与边界说明

提升仓库的开源协作友好度

让项目从“资料整理”更像“可复用的开源工具”
