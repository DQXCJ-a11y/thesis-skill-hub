# 第一章 · 绪论 · 深度审查包

> 本文件用于第二轮深入审查。第一轮请使用根目录的 `SKILL.md`。
> 使用方法：将本文件内容粘贴给已激活SKILL的AI，然后发送"请用这份深度审查包对我的第一章进行逐段审查"。

---

## 一、绪论的定位与审查原则

绪论是审稿人最先细读的部分。审稿人通过绪论判断这篇论文值不值得深入看。绪论的核心任务只有一个：让读者看完后清楚地知道——为什么做这件事、别人做到了什么程度、你做了什么、全文怎么安排。

**绪论不包含你自己的研究方法细节**，那是第3、4章的内容。绪论只是预告和铺垫。

---

## 二、1.1 研究背景与意义——逐段审查标准

### 2.1 四段递进结构（逐段检查）

| 段落 | 必须包含的内容 | 🔴 致命错误 | ✅ 合格标准 |
|------|-------------|-----------|-----------|
| 第一段 | 领域重要性与应用现状 | 只有"随着XX的发展"，无数据无政策 | 有宏观数据/政策/统计/行业报告支撑 |
| 第二段 | 现有技术的**具体痛点** | 痛点空洞或缺失 | 明确指出是精度不够、效率低、功能缺失还是场景未覆盖 |
| 第三段 | 研究意义（应用+学术） | 只写了一个维度的价值 | 同时点出应用价值和学术价值 |
| 第四段 | 引出本文 | 突然开始讲方法，没有过渡 | 以"基于上述背景，本文……"自然过渡 |

### 2.2 结尾段固定句式（审查时对照）

合格的结尾段应包含以下要素：
```
基于上述背景，本文面向[应用场景]，围绕[核心研究对象]展开研究，
探索在[约束条件]的前提下，实现[目标]的可行路径。
从[应用/工程]层面看，本文研究有助于……
从[学术/研究]层面看，现有研究尚无……本文所开展的研究填补了这一空白，为……提供了参考。
```

**检查点：** 结尾段是否同时出现"应用价值"和"学术价值"两个层面？如果只有一个，标记为 🟡 建议修改。

### 2.3 素材质量检查

- 是否引用了近1-2年的权威数据或政策背景？
- 背景数据是否可验证（有具体来源），而非AI编造的模糊数字？
- 是否有至少2-3篇权威引用支撑背景段？

## 三、1.2 国内外研究现状——逐节审查标准

### 3.1 分节逻辑检查

**核心原则：** 分节必须以你的研究内容/创新点为中心，不是按领域通行方向划分。

**检查方法：**
1. 列出论文第3、4章中使用的核心技术（A、B、C）
2. 检查1.2的每个小节是否对应其中一项
3. 如果某小节的内容与第3、4章无直接关联 → 🔴 冗余内容

**实例参照（电气工程方向）：**
- 1.2.1 对应研究对象（CPS技术发展）
- 1.2.2 对应核心方法（电能质量监测技术）
- 1.2.3 对应实现平台（嵌入式监测装置）
- 三个小节恰好对应三个视角，每个视角都与创新点直接关联

### 3.2 单篇文献介绍质量（逐条检查）

每篇文献的介绍必须有三要素：

| 要素 | 内容 | 检查方法 |
|------|------|---------|
| ① 研究问题 | 这篇论文研究的是什么 | 是否有一句话背景？ |
| ② 核心贡献 | 提出了什么方法/系统 | 是否说清楚了做了什么？ |
| ③ 效果/局限 | 取得了什么效果或存在什么不足 | 是否有评价性内容？ |

**🔴 流水账判定标准：** 如果连续3篇以上文献的介绍都是"XX做了这个，YY做了那个"，没有过渡句、没有逻辑连接、没有评价 → 判定为流水账。

### 3.3 过渡句检查

在每两篇文献介绍之间，检查是否有以下类型的过渡：

| 场景 | 合格句式示例 |
|------|-----------|
| 首篇引入 | "在[方向]领域，[作者]等率先提出了……" |
| 后续跟进 | "在此基础上，[作者]进一步……" |
| 指出局限 | "然而，上述方法均……存在……的局限" |
| 小节末 | "综上所述，目前[方向]研究已……但在……方面尚存在……" |

### 3.4 每小节末尾总结段（必须有）

每个小节末尾必须有一段"综上+引出本文"的总结。检查要素：
- [ ] 是否总结了本小节介绍的工作的共同进展
- [ ] 是否指出了现有研究的共同不足
- [ ] 是否有"这一现状表明……也是本文工作的出发点"类过渡

**🔴 缺少末尾总结段 = 必须修改**

### 3.5 引用质量检查

| 类型 | 要求 | 优先级 |
|------|------|--------|
| 顶刊顶会（近3年） | 每个小节至少1-2篇 | ★★★ 最高 |
| 硕博学位论文 | 可作为发展脉络来源，2-3篇 | ★★ |
| 综述类论文 | 如有高质量综述，引用一篇覆盖发展历史 | ★★★ |
| 国家/行业标准 | 技术定义、指标定义必须引用标准 | ★★★ 必须 |
| 博客/网页 | 不可作为唯一来源 | ❌ |

## 四、1.3 研究内容与创新点——逐条审查标准

### 4.1 研究内容（逐条检查）

每条研究内容须包含三要素："针对[问题] → 做了[什么] → 实现了[效果]"

**检查方法：** 逐条对照第3-5章，看是否一一对应。
- 研究内容提到了，但后续章节没有对应内容 → 🔴 虚假承诺
- 后续章节有重要内容，但研究内容没提 → 🟡 遗漏

### 4.2 创新点（逐条检查）

**绝对禁止的写法（逐条扫描）：**
- "本文系统地介绍了……" → 🔴 这不是创新
- "本文总结了……" → 🔴 这不是创新
- "本文研究了……" → 🟡 太模糊，需要具体化

**合格标准：** 每条创新点必须说清楚"新"在哪里——是新方法、新架构、新应用场景、还是新的集成方式。

### 4.3 技术路线图检查

- [ ] 是否有技术路线图？（没有 → 🔴 必须补充）
- [ ] 图是否为矢量或高清格式？（模糊 → 🟡 建议重绘）
- [ ] 图下是否有一段文字描述路线逻辑？（没有 → 🟡 建议补充）
- [ ] 路线图是否展示了"从问题到结论"的完整流程？

## 五、1.4 论文结构安排——审查标准

逐章检查每章的描述：

| 检查项 | 🔴 错误示例 | ✅ 合格示例 |
|--------|-----------|-----------|
| 是否超越标题 | "第3章为硬件设计，介绍了硬件设计" | "第3章基于TMS320F28335完成硬件平台设计，包括信号采集、调理与通信接口" |
| 是否说明做了什么 | "第5章为实验" | "第5章搭建实验平台，对系统测量精度和通信可靠性进行验证分析" |

## 六、绪论完整错误清单（逐项扫描）

| # | 错误类型 | 错误表现 | 正确做法 |
|---|---------|---------|---------|
| 1 | 研究背景太空洞 | 只说"随着XXX的发展……越来越重要" | 用具体痛点/数据说明必要性 |
| 2 | 研究现状与研究无关 | 把整个领域所有方向都堆进去 | 只写与创新点直接相关的方向 |
| 3 | 研究现状是流水账 | "XX做了这个，YY做了那个"无逻辑 | 用过渡句串联，每小节末总结不足 |
| 4 | 创新点不具体 | "本文在XXX领域做出了贡献" | "针对X问题，提出了Y方法，取得Z效果" |
| 5 | 结构安排只重复标题 | "第3章为硬件设计，介绍了硬件设计" | 每章说明做了什么、解决什么问题 |
| 6 | 引用不规范 | 介绍了论文但没有引用编号 | 每提到一篇论文必须加引用标注 |
| 7 | 缺少技术路线图 | 研究内容只有文字没有图 | 必须绘制技术路线图 |
| 8 | 研究意义只有一个维度 | 只写应用价值或只写学术价值 | 两个维度都要点出 |

## 七、绪论写作的推荐流程

正确的写作顺序（非常重要）：
1. 先确定第3、4章内容（知道你做了什么）
2. 再写1.2研究现状（按创新点找文献）
3. 再写1.1研究背景（从现状中提炼痛点）
4. 再写1.3研究内容（总结你的工作）
5. 最后写1.4论文结构安排

**绪论是"事后总结的前言"，必须在知道自己做了什么之后才能写好。**
